Build a local Carnatic lesson replay app for a student returning after class. Import one recorded class, find the teacher's full rendition and sung examples, and use the spoken corrections to decide what to practice. A student must be able to hear the full song and jump from a correction to the relevant sung phrase. Keep the original audio, a chronological Zoom-like playable transcript, and a concise practice summary. Make uncertainty visible. Only transcribe speech actually heard. Distinguish speech, singing, and the continuous shruti drone. Avoid claiming speaker identity or exact lyric/swara recognition without evidence.

V1 accepts 16 kHz mono signed 16-bit little-endian PCM WAV, with an explicit file size/duration limit and helpful error messages. Process recordings on-device, including speech recognition. The trusted runtime image contains Node 22, whisper-cli from whisper.cpp v1.8.2, and a multilingual model in WHISPER_MODEL=/opt/whisper/ggml-base.bin. Invoke it with fixed argument arrays on server-generated local paths in a private scratch directory. Use local Whisper timestamps together with audio features (e.g. periodicity, pitch stability/movement and amplitude relative to a quiet drone) to locate sung sections, including when speech recognition yields no words during a song. Whisper segment timestamps can be coarse; where useful transcribe isolated speech regions for alignment. Handle a recording with no song or no correction honestly. Persist imports in DATA_DIR. Restrict access to the local app, avoid external services and browser/CDN dependencies, and serve only intended lesson content to loopback users.

Public testable interface: POST /api/lessons with raw audio/wav returns the finished lesson as JSON (201 or 200). The shape includes { id, song: { start, end } or null, corrections: [{ text, start, end, phraseStart, phraseEnd }], transcript: [{ start, end, text }] }. Times are seconds from the beginning. GET /api/lessons/:id returns the saved lesson. GET /api/lessons/:id/audio returns the exact uploaded WAV and supports seeking. GET /health and GET / serve the health check and usable app. Async status is optional, but keep this synchronous small-file endpoint working. Provide tests through node --test that can run in a bounded local container.

Design for a parent and a student sharing a laptop after class: a clear import action, a lesson library, obvious Play full song and correction/phrase playback, chronological transcript next to the lesson summary on wide screens. Use comfortable type, keyboard-accessible controls, and a layout that works on a phone. An original synthetic lesson and another with different timing will be uploaded as black-box acceptance tests. The app only receives the audio.
